# 아키텍처

## 처리 순서

```text
원문
→ KoreanTTSNormalizer: written form을 한국어 발화형으로 변환
→ G2P: 영어 철자화와 한국어 표면 발음 생성
→ TTS
```

`g2p(text)`는 두 단계를 순서대로 실행합니다. 중간 발화형만 필요하면
`normalizer(text)`를 사용합니다. 예를 들어 노멀라이저가 `16%`를 `십육 퍼센트`로
만들고, G2P 음운 단계는 이를 `심뉵 퍼센트`로 바꿉니다.

## 노멀라이저

```text
NFC·입력 검증
→ 보호 구간 탐지
→ 우선순위 토큰 스캔
→ 확정 규칙 변환
→ 필요한 숫자만 Kiwi 형태소 자질 기반 통계 모델 판별
→ 보존 정책·진단
```

통화·날짜·시간·범위처럼 표기가 읽기를 확정하는 토큰은 규칙이 담당합니다. 숫자
판별 모델은 카운터와 맨숫자처럼 문맥이 필요한 후보에만 개입하며, Kiwi가 제공한
주변 형태소 자질을 사용합니다. 분석 실패나 근거 부족 시 규칙 결과를 유지합니다.

문자열 API는 원문 span 생성을 생략하고, 일반 한글 문장은 토큰 스캐너도 건너뜁니다.
노멀라이저의 상세 `convert()`만 원문 좌표·rewrite·진단을 만듭니다.

## G2P

```text
KoreanTTSNormalizer
→ NFC·입력 검증
→ 보호·숫자·외국어 라우팅
→ ASCII 영어를 알파벳 이름으로 변환
→ HARD 경계 병합
→ Kiwi와 한국어 음운 규칙 적용
→ 최종 출력 검증
```

숫자는 앞선 노멀라이저가 읽고 G2P 음운 단계에서는 HARD 경계로 통과합니다.
지원하지 않는 문자는 보존합니다. 형태소 분석기와 음운 엔진은 교체할 수 없습니다.

## 공유 상태

- 정규식·규칙표: 모듈에서 한 번 컴파일
- Kiwi·숫자 모델: 프로세스에서 지연 생성 후 재사용
- 분석 결과·segment·진단: 호출마다 생성
- 사용자 사전: 생성자에서 trie로 컴파일하며 빈 사전은 보관하지 않음

배치 API는 순차 지연 iterator입니다. Python 스레드는 Kiwi 처리량을 높이지 못했으므로
내부 병렬 옵션을 두지 않습니다. 여러 코어가 필요하면 프로세스 워커를 사용합니다.
